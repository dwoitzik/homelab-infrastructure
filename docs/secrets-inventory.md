# Secrets Inventory

Where every credential lives, and how it gets from source to runtime. Written 2026-06-19
after a routine check found no single doc answered "where is X stored" — this is that doc.

## Source of truth by category

| Category | Source of truth | Synced to |
|---|---|---|
| Ansible-managed host secrets (DNS, proxy, game server, etc.) | `ansible/group_vars/all/vault.yml` (Ansible Vault) | Rendered into configs/env files on the target host during playbook run |
| k3s application secrets | HashiCorp Vault (`vault` namespace, KV v2 at `secret/`) | Kubernetes Secrets via ExternalSecrets Operator (`ClusterSecretStore: vault`) |
| Vault unseal keys | `ansible/group_vars/all/vault.yml` (`vault_unseal_key_1/2/3`) | Mirrored into k8s Secret `vault-unseal-keys` (`vault` namespace) for the `vault-unseal` auto-unseal sidecar — see `kubernetes/system/vault/unseal.yml` |
| TLS certificates | cert-manager (Let's Encrypt DNS-01 via Cloudflare) | `wildcard-woitzik-dev-tls` Secret, replicated into every namespace that needs it |
| Terraform state / backend creds | `terraform.tfvars` per stack (not committed) | Read directly by Terraform / Atlantis |
| GitHub PATs (Renovate, Atlantis) | Vault `secret/renovate`, `secret/atlantis` | ExternalSecret → `renovate-token` / `atlantis-secrets` |

## HashiCorp Vault (k8s-side secrets)

Vault runs in the `vault` namespace, Raft storage, **Shamir-sealed** — it re-seals on every
pod restart and needs 2 of the 3 unseal keys above. As of 2026-06-19 this is automated:
the `vault-unseal` Deployment polls `vault status` every 30s and runs `vault operator unseal`
with keys 1+2 from the `vault-unseal-keys` Secret. If that Deployment is ever down, unseal
manually:

```bash
kubectl exec -n vault vault-0 -- vault operator unseal <key_1>
kubectl exec -n vault vault-0 -- vault operator unseal <key_2>
```

ExternalSecrets Operator (`external-secrets` namespace) reads from Vault KV v2 via the
`ClusterSecretStore` named `vault`, and writes plain k8s Secrets into whichever namespace
the ExternalSecret resource lives in. If Vault was just unsealed and an ExternalSecret is
stuck on a stale error, force a resync:

```bash
kubectl annotate externalsecret -n <ns> <name> reconcile.external-secrets.io/force-sync=$(date +%s) --overwrite
```

## Plaintext leak remediation status

**Git history purge completed 2026-06-22.** Every known plaintext secret was removed from
the full commit history (`git filter-repo --replace-text`, 491 commits across the only
branch that mattered — `main`). 28 other stale branches that still contained the
unscrubbed history were deleted both locally and on GitHub; `git reflog expire` + `git gc`
removed the now-unreachable objects locally before re-verifying. A full `gitleaks detect`
afterward found only the known `ROADMAP.md` documentation-text false positive. History was
force-pushed — this rewrites all commit hashes, so any existing local clone of this repo
needs `git fetch && git reset --hard origin/main` to pick up the clean history.

This closes the exposure from the repo being public, but does not by itself rotate the
underlying credentials — a value that was once exposed should still be treated as
compromised even after it's gone from git. Rotation status below.

## Rotation notes

- **Vault unseal keys**: rotating requires `vault operator rekey` — update both the Ansible
  Vault entry and the `vault-unseal-keys` k8s Secret afterward, or auto-unseal breaks silently.
- **Cloudflare tunnel token**: rotate in Cloudflare Zero Trust dashboard, then update
  `cloudflare_tunnel_token` in Ansible Vault and re-run the relevant playbook (cloudflared
  reads it as a k8s Secret via ExternalSecret, not directly from Ansible).
- **GitHub PATs**: both Atlantis and Renovate use fine-grained PATs with expiry — set a
  calendar reminder, there's no automated rotation.
